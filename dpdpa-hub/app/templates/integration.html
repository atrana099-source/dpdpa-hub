Integration & API

Two ways to connect your booking systems.

1. Embeddable widget

Paste this on a page of your website. Allow your site in the CORS_ORIGINS setting.

<div id="dpdpa-consent" data-slug="guest-booking" data-base="{{ base }}"></div>
<script src="{{ base }}/widget.js" defer></script>

The widget has no OTP check. For production, call the API from your own backend after the person is signed in, or verify the mobile or email first.

2. Server-to-server API

Send the key in the X-API-Key header. Create keys under API keys.

GET  {{ base }}/api/v1/notices/<slug>
POST {{ base }}/api/v1/consents            {"principal_ref":"user@example.com","notice_slug":"guest-booking","granted":["BOOKING","TRIP_COMM"]}
POST {{ base }}/api/v1/consents/withdraw   {"principal_ref":"...","notice_slug":"guest-booking","purposes":["MARKETING"]}
GET  {{ base }}/api/v1/consents?principal_ref=...
GET  {{ base }}/api/v1/consents/check?principal_ref=...&purpose=MARKETING
GET  {{ base }}/api/v1/receipts/<receipt_id>
POST {{ base }}/api/v1/dsr                 {"type":"Erasure","name":"...","contact":"...","identifier":"..."}

Check /consents/check before every marketing or optional communication.
